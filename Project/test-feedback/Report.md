## 1. Test Scripts

### วัตถุประสงค์การทดสอบ
ตรวจสอบว่าผู้ใช้เข้าใจและใช้งาน 4 ฟีเจอร์หลัก (Happy Hour, Pre-order, คูปองส่วนบุคคล, สะสมแต้ม) ใน Prototype ได้จริงหรือไม่ และเก็บ feedback เพื่อวางแผน mode ถัดไป

### คำแนะนำก่อนเริ่มทดสอบ (พูดกับผู้ทดสอบ)
> "วันนี้จะให้คุณลองใช้แอปต้นแบบร้านเครื่องดื่มนะคะ ไม่มีคำตอบถูกหรือผิด อยากให้คุณคิดออกเสียงระหว่างทำด้วยว่าคุณกำลังคิดอะไรอยู่ค่ะ"

### Task ที่ให้ผู้ทดสอบทำ
1. เปิดแอปครั้งแรก ลองดูว่าตอนนี้ร้านมีโปรโมชันอะไรอยู่บ้าง (หน้าหลัก)
2. ลองสั่งล่วงหน้า (Pre-order) ชาไข่มุก ที่สาขา OWM Central Rama 2 เวลา 16:00 น.
3. เปิดหน้า Happy Hour แล้วบอกว่าส่วนลดเท่าไหร่ ใช้ได้ถึงกี่โมง
4. เปิดหน้า "คูปองของฉัน" แล้วเลือกคูปองที่จะใช้วันนี้ พร้อมบอกเหตุผล
5. เช็คแต้มสะสมที่มีอยู่ แล้วลองดูว่าแลกของรางวัลอะไรได้บ้าง
6. กลับไปเช็คสถานะคำสั่งซื้อจาก Task 2 ว่าถึงขั้นตอนไหนแล้ว
7. สรุปให้ฟังว่าหน้าจอไหนที่เข้าใจง่าย/ยากที่สุด เพราะอะไร

### คำถามหลังทดสอบ (Post-test Interview)
- ฟีเจอร์ไหนที่ใช้งานง่ายที่สุด/ยากที่สุด เพราะอะไร?
- คุณเข้าใจไหมว่าโปร Happy Hour ใช้ได้ "ทุกวัน" หรือคิดว่าเป็นแค่วันนี้วันเดียว?
- เงื่อนไขของคูปองแต่ละใบชัดเจนพอไหม?
- มีฟีเจอร์อะไรที่คุณคาดหวังจะเห็นแต่ไม่มีในแอปนี้?
- ให้คะแนนความง่ายในการใช้งาน 1-5 พร้อมเหตุผล

## 3. What to do next from Test Feedback

### ประเด็นที่ต้องแก้ไข (เรียงตามความรุนแรง)

1. **ข้อมูลแบบ real-time ไม่เพียงพอ**
   สต็อกสินค้าไม่แสดงตอน pre-order และสถานะคำสั่งซื้อไม่มี ETA → กระทบความไว้ใจของลูกค้าโดยตรง โดยเฉพาะช่วง Peak Hour ที่ทีมงานเจอปัญหานี้ซ้ำในชีวิตจริงอยู่แล้ว

2. **ขาด error/warning message ที่ชัดเจน**
   คูปองที่ยังไม่เข้าเงื่อนไขไม่มีข้อความอธิบาย ทำให้ผู้ใช้สับสนว่าทำไมใช้ไม่ได้

3. **การเชื่อมโยงระหว่างฟีเจอร์ยังไม่ลื่นไหล**
   Happy Hour กับ Pre-order เป็นคนละหน้า ไม่มีทางลัดเชื่อมกัน ทั้งที่ควรใช้คู่กันเพื่อลดปัญหาคิวช่วง Peak

4. **Nice-to-have**
   ปุ่ม "แลก" ในหน้าสะสมแต้มอยู่ใกล้ตัวเลขแต้มเกินไป เสี่ยงกดพลาด

### Mode ที่ต้องกลับไปทำต่อ
ทีมควรกลับไปสู่ **Ideate → Prototype (Iterate)** เฉพาะจุด ไม่ใช่เริ่มใหม่ทั้งหมด เพราะแนวคิดหลัก (Happy Hour + Pre-order + คูปอง + สะสมแต้ม) ยังตอบโจทย์ pain point ของร้านค้าได้ดี เพียงแต่ต้องปรับรายละเอียดด้าน UI/UX และการแสดงข้อมูลแบบ real-time

## 4. Next Mode(s) Based on User Feedback

จากฟีดแบ็กที่ได้ ทีมควร **iterate กลับไปที่ขั้น Prototype** อีกรอบ (ไม่ใช่ Empathize หรือ Define ใหม่) เพราะ:

- ปัญหาที่พบส่วนใหญ่เป็นปัญหาเชิง **Interaction Design และ Information Design** (ไม่แสดงสต็อก, ไม่มี ETA, ไม่มี error message) ไม่ใช่ปัญหาที่ตัว Insight หรือ Final Elected Idea ผิดพลาด → **ไม่จำเป็นต้องย้อนกลับไป Empathize/Define**
- ควรทำ **iteration** ก่อน โดยเน้น 3 เรื่อง:
  1. เชื่อมข้อมูลสต็อกสินค้าแบบ real-time เข้าหน้า pre-order
  2. เพิ่ม ETA/ลำดับคิวในหน้าสถานะคำสั่งซื้อ และ popup ยืนยันในหน้าสะสมแต้ม
  3. ออกแบบ error state ที่ชัดเจนในหน้าคูปอง พร้อมลิงก์เชื่อม Happy Hour ↔ Pre-order
- หลังจากปรับแล้ว ควรกลับเข้าสู่ **Test อีกรอบ (Usability Testing Round 2)** เพื่อยืนยันว่าปัญหาความไว้ใจ (trust) ในข้อมูลสต็อก/คิวได้รับการแก้ไขจริง ก่อนจะพัฒนาเป็น Mid/High-fidelity prototype ต่อไป
